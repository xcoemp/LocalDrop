# android-kit

The project-specific half of the Android app. `src-tauri/gen/android/` is
generated by `tauri android init` and is **not committed**, so everything here
has to be copied back into it after a fresh clone or any re-`init`.

Skipping this does not produce a build error. It produces an app that compiles,
installs, launches, and never finds a peer.

---

## Applying it

From the repo root, after `pnpm tauri android init` has created
`src-tauri/gen/android/`:

```bash
cd src-tauri
KIT=android-kit
APP=gen/android/app/src/main/java/app/localdrop

# 1. Kotlin sources
cp $KIT/MainActivity.kt      $APP/
cp $KIT/LocalDropNetwork.kt  $APP/
cp $KIT/LocalDropService.kt  $APP/
cp $KIT/LocalDropScreen.kt   $APP/
cp $KIT/LocalDropStorage.kt  $APP/

# 2. ProGuard rules for the JNI surface
cp $KIT/proguard-jni.pro gen/android/app/proguard-jni.pro

# 3. Gradle build task fix
cp $KIT/BuildTask.kt gen/android/buildSrc/src/main/java/app/localdrop/kotlin/BuildTask.kt
```

Then apply the two things that are edits rather than copies:

- **`AndroidManifest.permissions.xml`** — merge into
  `gen/android/app/src/main/AndroidManifest.xml`. The permissions go inside
  `<manifest>`, the `<service>` inside `<application>`, and the `<manifest>`
  root needs `xmlns:tools="http://schemas.android.com/tools"` added.
- **[`SigningConfig.patch.md`](SigningConfig.patch.md)** — apply to
  `gen/android/app/build.gradle.kts`. Only needed for a distributable release;
  `pnpm android:dev` works without it.

`proguard-jni.pro` needs no wiring: the generated `build.gradle.kts` already
picks up `**/*.pro` under `app/` via `fileTree(".")`.

## What each file is for

| File                              | Destination                                   | Without it                                                                                                         |
| --------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `BuildTask.kt`                    | `buildSrc/.../kotlin/BuildTask.kt`            | **Build fails** — `Cannot find module '…/src-tauri/tauri'` under pnpm; also the Gradle 9 `Project.exec` removal    |
| `AndroidManifest.permissions.xml` | merge into `app/src/main/AndroidManifest.xml` | No permissions — discovery and the foreground service both fail silently                                           |
| `MainActivity.kt`                 | `app/src/main/java/app/localdrop/`            | No multicast-lock lifecycle, no all-files prompt, no keyboard inset, white nav bar over a dark UI                  |
| `LocalDropNetwork.kt`             | same directory                                | **The radar stays empty forever, with no error.** Android drops inbound UDP broadcast without a held MulticastLock |
| `LocalDropService.kt`             | same directory                                | Transfers die as soon as the app is backgrounded                                                                   |
| `LocalDropScreen.kt`              | same directory                                | Long transfers drop when the screen sleeps                                                                         |
| `LocalDropStorage.kt`             | same directory                                | Folder sends walk the tree and then transfer nothing                                                               |
| `proguard-jni.pro`                | `app/proguard-jni.pro`                        | R8 strips the JNI entry points; release builds crash where debug builds work                                       |
| `SigningConfig.patch.md`          | patch `app/build.gradle.kts`                  | Release APK is unsigned; the device says only "App not installed"                                                  |
| `BuildTask.patch.md`              | reference for `BuildTask.kt`                  | —                                                                                                                  |

## Verifying it took

Three checks, cheapest first. None of them needs a full four-ABI build.

**1. Signing config resolves.** Seconds, no compilation:

```bash
cd src-tauri/gen/android
powershell -NoProfile -ExecutionPolicy Bypass \
  -File ../../../scripts/msvc-env.ps1 ./gradlew.bat -q :app:signingReport --console=plain
```

Every `*Release` variant must show `src-tauri/localdrop-release.jks` and alias
`localdrop`. If they show the debug keystore, or `Store:` is blank, the
`SigningConfig` patch is missing or its path is wrong — see the `../` vs `../../`
trap in [`SigningConfig.patch.md`](SigningConfig.patch.md).

**2. Manifest merged.** The merged file should carry all ten permissions, the
`tools` namespace, and the service:

```bash
cd src-tauri
grep -o 'android\.permission\.[A-Z_]*' gen/android/app/src/main/AndroidManifest.xml | sort -u | wc -l   # 10
grep -c 'xmlns:tools'    gen/android/app/src/main/AndroidManifest.xml                                   # 1
grep -c 'LocalDropService' gen/android/app/src/main/AndroidManifest.xml                                 # 1
```

Count `android.permission.` rather than `uses-permission`: the
`MANAGE_EXTERNAL_STORAGE` entry carries a `tools:ignore` attribute and so is
wrapped across two lines, which makes a line count read one short.

**3. Multicast lock actually held**, on a device. This is the one that cannot be
checked from the build, and the one whose absence looks exactly like a bug in
the Rust:

```bash
adb logcat -s LocalDropNetwork LocalDropService RustStdoutStderr WifiService
```

The system's own line is the independent confirmation — our log only says we
asked:

```text
WifiService       : acquireMulticastLock uid=10632 lockTag=localdrop-discovery
LocalDropNetwork  : multicast lock acquired
```

## Class loading, if you add to this

Anything calling into the app's own Kotlin from Rust must resolve the class
through the **activity's class loader**, not a JNI string descriptor. On a
thread attached from native code `FindClass` uses the system loader, which sees
framework classes only: `android/net/Uri` resolves, `app.localdrop.*` throws
`ClassNotFoundException`. This silently disabled two features before it was
found. Use `find_app_class` in `src-tauri/src/android.rs`.

Keep the class names here and in the manifest in sync. A `<service
android:name>` that matches no class is not a build error — it throws the first
time the service is started, on a device.
