# Patch: release signing in `app/build.gradle.kts`

**Required after every `tauri android init`.** `gen/android/` is generated and
not committed, so this is lost whenever the project is regenerated — and losing
it fails _silently_: the build succeeds and emits
`app-universal-release-unsigned.apk`, which the device then refuses to install
with nothing but **"App not installed"**.

Apply to `gen/android/app/build.gradle.kts`.

---

## 1. Import and read the properties file

`java.util.Properties` and `java.io.File` are needed at the top of the file:

```kotlin
import java.util.Properties
import java.io.File
```

Then, above the `android { }` block:

```kotlin
/**
 * Release signing.
 *
 * `keystore.properties` and the .jks live in `src-tauri/`, deliberately outside
 * `gen/` — everything under gen/ is regenerated by `tauri android init`, and
 * losing the key would make it impossible to ship an update that upgrades an
 * installed copy. Neither file is committed.
 *
 * The path is `../../`, not `../`: `rootProject` here is `src-tauri/gen/android`,
 * so reaching `src-tauri/` takes two levels (android -> gen -> src-tauri).
 */
val keystoreDir = rootProject.file("../../")

val keystoreProperties = Properties().apply {
    val propFile = File(keystoreDir, "keystore.properties")
    if (propFile.exists()) {
        propFile.inputStream().use { load(it) }
    } else {
        logger.warn("keystore.properties not found at ${propFile.absolutePath}; release will be UNSIGNED")
    }
}
```

## 2. Declare the signing config

Inside `android { }`:

```kotlin
    signingConfigs {
        create("release") {
            keystoreProperties.getProperty("storeFile")?.let {
                // Resolved against the same directory as keystore.properties,
                // so `storeFile=localdrop-release.jks` means "next to me".
                val ks = File(keystoreDir, it)
                if (!ks.exists()) {
                    throw GradleException(
                        "keystore.properties names storeFile='$it' but ${ks.absolutePath} does not exist. " +
                            "Fix the path or remove keystore.properties to build unsigned."
                    )
                }
                storeFile = ks
                storePassword = keystoreProperties.getProperty("storePassword")
                keyAlias = keystoreProperties.getProperty("keyAlias")
                keyPassword = keystoreProperties.getProperty("keyPassword")
            }
        }
    }
```

## 3. Apply it to the release build type

Inside `buildTypes { getByName("release") { ... } }`, as the first statement:

```kotlin
            // Absent on a fresh checkout; the build still succeeds, just unsigned.
            if (keystoreProperties.getProperty("storeFile") != null) {
                signingConfig = signingConfigs.getByName("release")
            }
```

---

## The `../` vs `../../` trap

This cost a full four-ABI LTO build to discover. With `rootProject.file("../keystore.properties")`:

- `rootProject` is `src-tauri/gen/android`, so the path resolves to
  `src-tauri/gen/keystore.properties` — which does not exist
- `propFile.exists()` is therefore false and the `Properties` object stays empty
- `getProperty("storeFile")` returns null, so the `?.let` body never runs and
  `signingConfig` is never assigned
- Gradle builds and packages happily, emitting an **unsigned** APK

Nothing in the build output mentions signing, the keystore, or the missing file.
The `logger.warn` and the `GradleException` above exist so the next person gets
told immediately instead of finding out from a phone.

---

## Verifying without a full build

`signingReport` resolves the config in seconds and prints the keystore it
actually found:

```bash
cd src-tauri/gen/android
powershell -NoProfile -ExecutionPolicy Bypass \
  -File ../../../scripts/msvc-env.ps1 ./gradlew.bat -q :app:signingReport --console=plain
```

Expected, for the release variants:

```text
Config: release
Store: .../src-tauri/localdrop-release.jks
Alias: localdrop
```

If `Store:` is blank or the release variants show the debug keystore, the path
above is wrong again.

`pnpm deploy:android` also refuses to publish an unsigned artifact and runs
`apksigner verify` on whatever it does publish, so the mistake cannot reach a
release a second time.
